# Stage 2 — Run

> Project Stage: 02  
> Project: Class Concept Robot  
> Purpose: Execute a working robot program and establish a reliable baseline before making any modifications.

---

# Stage Purpose

Before changing software,

you must first understand how it behaves.

This stage is intentionally simple.

You will run a robot program that already works.

You are **not** expected to understand every line of code.

Instead, you should simply observe:

- what the robot does,
- how the program behaves,
- what parts of the code appear to control the robot.

This working program becomes your reference for the rest of the project.

---

# Goal

Run the prepared robot project without changing anything.

Your objective is **not** to improve the program.

Your objective is to experience the original behavior.

At the end of this stage you should be able to say:

> "I know what the original robot does."

---

# What You Should Observe

Watch the robot carefully.

Do not only ask:

> "Does it work?"

Instead ask:

- What actions does the robot perform?
- What information does the robot appear to remember?
- Which behavior changes over time?
- Which behavior never changes?

Do not worry if you cannot answer every question.

Observation comes before explanation.

---

# Run the Starter Project

Execute the prepared starter program.

The project should already compile and run successfully.

Examples of expected behavior:

- Robot moves forward.
- Robot stops.
- Robot changes direction.
- Robot changes speed.
- Robot responds to a simple input.

The exact behavior depends on the project version.

---

# Your Mission

While the robot is running,

try to identify only three things.

1.

Which part of the code seems to make the robot move?

---

2.

Which part of the program seems to remember information?

---

3.

Which part is still completely unclear?

Do not search for the answer yet.

Simply notice your current understanding.

---

# Do Not Modify Anything Yet

This stage intentionally avoids changing code.

Even if you already know how to improve the project,

wait.

Every modification should be compared with a working reference.

That comparison is impossible if the original behavior is forgotten.

---

# Expected Result

By the end of this stage,

you should have:

- executed the project,
- observed the robot,
- identified one interesting behavior,
- identified one confusing part,
- prepared yourself to make one controlled modification.

Perfect understanding is **not** required.

---

# Common Beginner Mistakes

Many beginners immediately begin changing code.

Examples include:

- changing several variables,
- deleting functions,
- reorganizing files,
- adding new features.

Avoid doing this.

One of the most important engineering skills is learning to observe before changing.

---

# Completion Check

Before continuing:

- [ ] The robot runs successfully.
- [ ] I observed the original behavior.
- [ ] I identified one interesting behavior.
- [ ] I identified one confusing part.
- [ ] I have not modified the code.

---

# Think About

> The robot already works.

If it already works,

why might programmers later decide to reorganize this code?

You do **not** need the answer yet.

The next stage begins exploring that question.
