# Stage 3 — Modify

> Project Stage: 03  
> Project: Class Concept Robot  
> Purpose: Extend a working robot program and discover how software naturally becomes more difficult to manage.

---

# Stage Purpose

Until now,

you have worked with a robot program that already functions.

Now you will begin extending it.

At first,

adding one more feature seems easy.

Then another.

Then another.

Eventually,

you may notice something unexpected.

The robot still works.

But the code becomes harder to understand.

This stage is designed to let you experience that moment.

---

# Goal

Add one small feature to the existing robot program.

The purpose is **not** to redesign the software.

The purpose is to experience how software changes as functionality grows.

---

# Suggested Modifications

Choose **one** small modification.

Examples:

- add a speed setting,
- change the movement duration,
- add reverse movement,
- add LED control,
- add another movement command,
- add a simple sensor response.

The exact task depends on the project version.

---

# Observe the Code

After making the modification,

do not immediately continue adding more features.

Pause.

Look at the code.

Ask yourself:

- Which function changed?
- Which variables changed?
- Which parts became longer?
- Which parts became harder to read?

The robot still works.

But does the program still feel simple?

---

# Compare Before and After

Compare the original version with your modified version.

Think about:

Original

↓

Easy to understand?

↓

Modified

↓

Still easy to understand?

Do not worry if the answer is "No."

That is exactly what this stage is designed to reveal.

---

# Your Mission

Without changing the overall design,

continue adding one or two small features.

After each feature,

ask yourself:

> Is the program becoming easier to understand,

or more difficult?

Do not redesign the software yet.

Simply observe.

---

# Important Rule

Do **not** introduce classes.

Do **not** reorganize the project.

Do **not** split the code.

The purpose of this stage is to experience the limitations of the current structure.

The solution comes later.

---

# Expected Result

By the end of this stage,

you should notice at least one of the following:

- the code is becoming longer,
- one function now performs several jobs,
- variables appear in many places,
- changing one feature affects another,
- finding specific behavior takes longer.

If you notice any of these,

the stage has succeeded.

---

# Common Beginner Reaction

Many learners immediately think:

> "I should reorganize everything."

Resist that temptation.

First,

experience the problem.

Only then does a better structure become meaningful.

---

# Completion Check

Before continuing:

- [ ] I added one or more small features.
- [ ] The project still works.
- [ ] I compared the original and modified versions.
- [ ] I noticed at least one source of growing complexity.
- [ ] I did not redesign the project yet.

---

# Think About

> If this robot eventually contained fifty different behaviors,

would you still organize the software exactly the same way?

You do not need to answer now.

Just keep the question in mind.
