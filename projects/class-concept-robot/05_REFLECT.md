# Stage 5 — Reflect

> Project Stage: 05  
> Project: Class Concept Robot  
> Purpose: Pause after completing the project and reflect on how your understanding changed.

---

# Stage Purpose

Congratulations.

You have reached the end of the project.

The robot works.

The project is complete.

But one question still remains.

> **What changed inside your own understanding while completing this project?**

This stage is not another coding exercise.

It is an opportunity to preserve the most valuable outcome of the project:

**your changing way of thinking.**

---

# Looking Back

At the beginning of the project,

you were asked one simple question.

> **What do you think a class is?**

You were not expected to answer correctly.

You only needed to remember your first impression.

Now,

look back.

Has your answer changed?

---

# This Project Was Never About Syntax

At first,

it may have seemed like a project about C++.

In reality,

it was a project about software structure.

You experienced:

- a working program,
- growing complexity,
- increasing relationships,
- the need for clearer responsibility.

Only then did the idea of a class begin to make sense.

The class was not introduced first.

The need for the class came first.

---

# Reflection Questions

Choose the questions that feel meaningful to you.

There is no correct answer.

---

## 1. What changed?

How is your current understanding different from the beginning?

Examples:

- I thought...
- I now realize...
- I did not notice...
- I was surprised that...

---

## 2. What became easier to understand?

Think about one concept that became clearer.

Examples:

- state,
- behavior,
- responsibility,
- software structure,
- relationships,
- code organization.

---

## 3. What still feels difficult?

Reflection is not about pretending everything is clear.

Examples:

- I still don't understand...
- I would like another example...
- I want to explore...

Recognizing an unanswered question is often an important step in learning.

---

## 4. What did this project teach beyond programming?

Did you notice something that also applies outside software?

Examples:

- organizing information,
- separating responsibilities,
- simplifying complexity,
- thinking before changing,
- observing before redesigning.

---

# Before You Write

Do not try to summarize the entire project.

Instead,

write about one or two moments that genuinely changed your thinking.

A short honest Reflection is usually more valuable than a long technical report.
