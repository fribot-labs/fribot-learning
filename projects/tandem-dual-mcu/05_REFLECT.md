# Stage 5 — Reflect

> **Project:** Tandem Dual MCU  
> **Stage:** 05_REFLECT  
> **Goal:** Reflect on how your understanding of system architecture changed through building a robot with two cooperating microcontrollers.

---

# Purpose

The robot has already moved.

The project itself is complete.

Now the most important question remains.

> **What changed in your understanding?**

Reflection is not another programming exercise.

It is an opportunity to preserve how your thinking has evolved.

The goal is not to describe every line of code.

The goal is to recognize how your mental model of a software system has changed.

---

# Before You Begin

Think back to the first day of this project.

How did you answer these questions?

- Why would anyone use two microcontrollers?
- What is the purpose of communication?
- Which processor is "in charge"?
- What makes a robot become one system?

Now compare those first impressions with what you understand today.

---

# Reflection Themes

You do not need to answer every question.

Choose the one that feels most meaningful.

---

## 1. Responsibility

Before this project,

how did you think about the role of a microcontroller?

How has that understanding changed?

---

## 2. Communication

At first,

communication may have seemed like simply sending data.

Now,

what role does communication play in a complete system?

---

## 3. System Thinking

When did you first realize that

two independent processors

could behave like

one robot?

---

## 4. Problem Solving

If the robot stopped moving,

how would you investigate the problem now?

Has your debugging process changed?

---

## 5. Collaboration

This project required two processors to cooperate.

Did it change the way you think about collaboration between software components?

Can you think of similar examples in software systems?

---

## 6. Engineering Perspective

What surprised you most while building the Tandem Dual MCU system?

Was it:

- the communication,
- the responsibility separation,
- the debugging process,
- or something else?

---

## 7. Remaining Questions

What still feels unclear?

Examples:

- I2C communication
- command packets
- timing
- synchronization
- role separation
- system architecture

Understanding what remains unclear is also part of learning.

---

## 8. Looking Ahead

If you continued this project,

which capability would you most like to add?

Examples:

- wireless communication
- autonomous driving
- obstacle avoidance
- multiple robots
- cloud connectivity
- AI decision making

Why?

# Key Insight

Many learners begin this project believing:

```text
Two processors

=

More hardware
```

Many finish the project realizing:

```text
Two processors

=

Separated responsibilities

+

Clear communication

+

One system
```

This change in perspective is one of the primary learning objectives.

# Final Message

The robot moved because two processors cooperated.

Learning happened because your understanding changed.

The real outcome of this project is not the robot's movement.

It is your ability to recognize that:

```text
Large systems become understandable

when responsibilities are clearly separated,

communication is well designed,

and every component contributes to one shared purpose.
```
